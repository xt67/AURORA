# AURORA v2.1 numerical execution correction

19 November 2026. This version retains the entire scientific design in [the v2 execution addendum](PUBLICATION_V2.md) and the historical simplified protocol. It changes only the classifier AMP initial loss scale, identically for every condition, before any test evaluation. The complete v2 addendum is also bound and archived as an input.

The first A/25%/seed-42 attempt at commit `befadbc` failed with a non-finite gradient before its first validation checkpoint. The failed attempt remains at `outputs/publication_v2/run_20261119/`. No test images were read. A training-only diagnostic reconstructed the first replacement-sampled batch with identical model initialization: both scales gave cross-entropy 0.977569580078125, but scale 65536 produced one non-finite gradient tensor, whereas scale 1 produced none. No optimizer step or holdout access occurred in that diagnostic; its source IDs and results are in `outputs/publication_v2_scaling_diagnosis.json`.

The correction sets GradScaler initial scale to 1.0, retaining its default growth interval of 2000. With 1000 updates per fit, the scale stays at 1 unless a numerical failure occurs. Every batch must have finite loss and gradients; a non-finite gradient stops the run rather than silently skipping an optimizer update. Thus all successful conditions still receive exactly 1000 updates and 16000 training draws. Full precision remains unchanged for GANs. Learning rates, models, data, splits, sampling, augmentation, counts, checkpoints, thresholds and analysis are unchanged. No model or protocol was chosen using test performance.

This is a documented numerical correction under the researcher's request to complete the remaining experiments. It is not an additional clinical, institutional or human-review approval. The corrected grid uses a new output directory, a new committed implementation and a new authorization record; no failed or historical artifact is overwritten.
